# Daemon, collectors & paper trading

Referenced from `CLAUDE.md`. Read this before touching the scheduler, collectors, detectors,
alert sink, `PaperTrader` / evaluators, or `PaperResolver`.

## Conventions
- **Detectors**: only `PollingDetector` survives (consumed by `PaperResolver`). The scheduler runs the resolver inside an `asyncio.TaskGroup` alongside collectors. Adding a new periodic worker = inherit `PollingDetector` and implement `_scan(sink)` + `_interval_seconds()`. Live signal emission lives on collectors (`SubgraphTradeCollector` writes directly to the alert sink).
- **Alert sink layering.** `AlertSink` is the only implementation of `IAlertSink`. `subscribe()` registers sync callbacks (PaperTrader uses this). `emit()` returns `True` on insert, `False` on dedupe hit.
- Each alert emitter must be in the `DetectorName` Literal in `src/pscanner/alerts/models.py`, otherwise the renderer KeyErrors. Today only `subgraph_copy` is in the Literal.
- **Severity ranking**: `SEVERITY_RANK = {"low": 0, "med": 1, "high": 2}` lives in `pscanner.alerts.models`. Evaluator gates use strict `[]` lookup on the configured `min_severity` (config-validated Literal) and lenient `.get(severity, -1)` on alert-provided values.
- **Paper-trading evaluators**: `pscanner.strategies.evaluators` has one `SignalEvaluator` Protocol implementation — `SubgraphCopyEvaluator`. `PaperTrader` walks the list and runs the first acceptor's parse/quality/sizing pipeline. Adding a new signal = one new class + one config block + one scheduler wiring. On daemon boot, `PaperTrader.replay_unbooked()` re-runs any alert from the last `paper_trading.replay_lookback_seconds` (default `0` = disabled) that has no `paper_trades` entry row, so a mid-day restart doesn't strand in-flight alerts (#105).
- **PaperResolver (`pscanner.strategies.paper_resolver`)** runs on the `PollingDetector` cadence (default 5 min via `paper_trading.resolver_scan_interval_seconds`). Each `_scan` does TWO passes over the open-position set: (1) `_refresh_stale_markets` walks distinct `condition_id`s and calls `refresh_market_cache_row` for any whose cache row is missing or not yet resolved (skips known-resolved via `_is_resolved`); (2) `_maybe_book_exit` runs the unchanged resolution check. Refresh failures are log-and-swallow — one bad market never blocks the rest of the scan. Ctor requires `data_client` + `gamma_client` kwargs (added in PR #186 follow-up).
- **`PaperTradesMetadataCollector` (`pscanner.collectors.paper_trades_metadata`)** periodically backfills `market_cache` + `event_tag_cache` for paper-trade `condition_id`s that aren't covered by the active-only sweeps in `MarketCollector` / `EventCollector`. Two phases per `poll_once`: phase 1a uses the slug-based refresh for cache-missing condition_ids; phase 1b uses the token-id path (`refresh_market_cache_by_asset_id`) for cache rows with `event_slug IS NULL`. Phase 2 then fills `event_tag_cache` from gamma `/events?slug=` for any event_slugs surfaced. Wired into the scheduler under `paper_trading.enabled`, 5-min cadence. Without this collector the copy-trading analyzer reports ~95% of subgraph_copy positions as `(uncategorized)`.
- **Constant sizing**: paper trades size off `starting_bankroll_usd` (constant), NOT running NAV. The `bankroll_exhausted` gate is removed by design — research config trades infinite paper bankroll for max data collection. NAV is still recorded on `paper_trades.nav_after_usd` for analysis (can be negative).

## CLI surface
- `pscanner run` (daemon) / `pscanner run --once` (single pass) / `pscanner status` (recent alerts)
- `pscanner watch <addr> [--reason TEXT]` / `pscanner unwatch <addr>` / `pscanner watchlist`
- `pscanner paper status` — aggregate NAV + per-wallet PnL + per-source breakdown table (one row per `(triggering_alert_detector, rule_variant)`; today every row is `(subgraph_copy, NULL)`).

## Tracked work in flight (issues filed)
- **SubgraphTradeCollector + SubgraphCopyEvaluator (#152, branch `feat/issue-152-subgraph-trade-collector`).** Daemon collector at `pscanner.collectors.subgraph_trades.SubgraphTradeCollector` polls the V2 Polymarket subgraph for trades by every active `wallet_watchlist` wallet and emits `subgraph_copy` alerts. Booking goes through `pscanner.strategies.evaluators.subgraph_copy.SubgraphCopyEvaluator` with anti-concentration sizing: per-wallet size is `bankroll * position_fraction * multiplier` where multiplier decays as the wallet's share of total subgraph_copy paper trades exceeds `1.0 / active_watchlist_size`, floored at `min_multiplier` (default 0.10). Watermark persists in `subgraph_watch_state.last_seen_ts`. Refuses to start when `GRAPH_API_KEY` is unset (preflight check). Sole live trade collector — the prior `/activity`-polling `TradeCollector` was removed in PR 5 of the dead-code cleanup wave. Pending: Task 11 desktop smoke before merging.

## Open follow-ups (no issues filed)
- **`PaperResolver` cold-start refresh burst.** First scan after deploy refreshes every distinct open-position `condition_id` whose cache row is missing or known-active. At `gamma_rpm=50` and ~700 stuck condition_ids that's ~15 min of API churn, competing with the events-catalog sweep. Mitigations not pre-implemented: stagger via `clock.sleep` at startup, or chunk the refresh set per scan. Will revisit if observed.
- **`paper status` rendering polish.** When `resolved_count=0`, `win_rate` shows `0.0%` (indistinguishable from "all losses"). Render as `-` instead. Also: the per-wallet PnL panel groups all wallet-less entries under an unlabeled `(no wallet)` row; should be labeled or merged with the per-source breakdown.
